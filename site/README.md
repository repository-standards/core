# site/ - the product's one web surface (zone 1, never shipped)

| Path | What |
|---|---|
| `index.html` | the landing - hand-authored; quotes `docs/positioning.md` verbatim (site-check enforces it) |
| `site.config.json` | brand, repo URL, top bar, sidebar links and (optionally) the page map. The ecosystem's shared form: any repo can carry this file and run the core's generator against its own markdown - one form, many sites, zero copied generators. It lives here rather than at the repo root because it configures this site, not the product |
| `docs/` | the docs site - GENERATED by `node tools/docsite.mjs` from the repo's own md, gitignored; never hand-edit |
| `CNAME` | the apex this directory is served under. GitHub Pages reads it from the deployed artifact and reassigns the domain to whichever repository published last, so only one repository in the ecosystem may carry it at a time - today that is the organization's site repository, and this copy stays dormant until that changes |

Deploy = serve this directory (landing at `/`, docs at `/docs/`) after running the
generator; CI builds and checks both on every push.
