headline: The loop now runs itself - lifecycle statuses, the clarify gate, guided align, and a PO explain mode

- **Lifecycle (ADR-010, Proposed)** - one arc for every artifact: ideas live in `docs/ideas/` (status-driven, no records until approved, graduation on approval); specs/records/docs are permanent and living; Spec Kit plan/tasks are ephemeral and removed at close by a code-verified cleanup; enabling work (tokens, access) goes front-matter -> tracker as blocking Stories, never spec prose. Tracker posture: GitHub Issues default (free), Jira (free <=10 users) and Linear (free, 250 active issues) as adapters behind one one-way bridge with key write-back.
- **Statuses** - a capability spec carries `Status: in-refinement -> ready-to-develop -> in-development -> live`; `ready-to-develop` is earned mechanically by the clarify gate (a `## Clarifications` section, zero open `[NEEDS CLARIFICATION]`) - the PO sees discovery vs build-ready at a glance.
- **The loop runs itself** - `AGENTS.md` now instructs agents to start the clarify loop unprompted on any feature talk, record deferrals ("leaving this to the technical side" is an answer), refuse to plan/tasks/mirror past a failing gate, and explain any record/spec in plain, persona-anchored language on request; `spec-kit-setup.md` documents the 5-layer enforcement stack (hook / gate / constitution / loaded context / bridge), field-proven in production (2026-07).
- **Guided align** - `align-to-standards` is re-entrant: resume from manifest+self-verify measurement, propose payoff-ordered waves, hand-hold, repeat until drift 0.
- **Personas + UX** - the standard's own roster (`docs/personas.md`: Standard-bearer, Spec-first PO, Buildable-truth Dev, Coding agent); catalog forks for the UX review lens (NN/g, ~5-user tests, JTBD) and design tokens (W3C DTCG v2025.10, three-tier).
- **Layer 2 app shell (DECISIONS #10)** - Better Auth (product auth) / `openid-client` shared module (enterprise SSO), Next 16 `proxy.ts` + rewrites -> Fastify with default-deny at both gates, CSS Modules + SCSS + DTCG tokens; the boot-verified `starter/` ("put up a repo and it runs") is scoped as STARTER-1 with a mechanical DoD.
- **Research** - the 2026 SDD landscape scan, tracker free tiers, and the PDLC gap map informed this wave's decisions; per the owner's rule, ALL research/working/idea notes live outside the repo - only the decided outputs (records, checklist rows, DECISIONS, positioning) land here.
- **One standard, two profiles (ADR-011, Proposed)** - `core` (keeps knowledge alive - every repo, even solo) vs `scale` (coordinates people - teams/enterprise), declared per manifest entry and verified per profile; adoption doc gains the picker; mechanics scoped as PROF-1. No light fork - one repo, rendered views.
- **Public-readiness** - personal notes and client-referencing research moved out of the repo; every client reference anonymized to "field-proven in a private production repo"; README/PRODUCT rewritten to writer-grade (the "reference your repo trues up to - and walks it there" positioning).
- **Every folder explains itself** - the taxonomy now fixes the three-section folder-README convention (what lives here / contents / why this shape + how to use it; `README.md` describes a folder, `catalog.md` stays reserved for curated lists like the decision checklist); new instances for `skills/` (with lifecycle-vs-transition classes), `docs/`, `tools/`.
- **Case studies** - `docs/case-studies/`: anonymized field evidence behind the rules (five seed cases: the silently skipped clarify, Proposed-does-not-mean-maybe, enabling work out of the spec, stacked PRs on a moving base, parallel record minting).
- **Utility never ships (ADR-009 revised while Proposed)** - transition skills (`align-to-standards`, `onboard-repo`, `modernize`, `greenfield-start`) are the standard repo's own machinery and no longer appear in `dist/` at all (`greenfield-start` runs before the target repo even exists); `dist/.claude/skills/` now carries exactly the nine lifecycle skills, guarded by reflect.
- **Core vs stacks made explicit (ADR-008 revised while Proposed)** - the shipped standard has two surfaces: a universal, language-agnostic core skeleton and `stacks/<technology>/` overlays (node-ts today, a second stack scoped as STACKS-2); the `dist/` name itself is reconsidered in STRUCT-1.
- **catalog -> checklist** - `decision-records/checklist.md` is the list of forks to consciously decide (a pre-flight checklist); the *catalogs* in the library sense are the record indexes, and the ADR index now carries a "Decides" gist per record so agents cluster-read instead of opening everything.
- **Fifth persona: the Owner** - the company/project owner who cannot audit code himself and buys assurance instead: a community-vetted, versioned standard whose green self-verify proves his teams ship quality (and makes his repos transferable assets); deliberately not a "project manager" - he sits above delivery.
- **FAQ + model guidance** - `docs/faq.md` (eight canonical adopter answers); `adoption.md`: prefer the strongest model at max thinking for the transition, and the explicit reassurance that weaker models finish the job - the process is re-runnable and lossless, the falling drift number is the progress bar. The human docs site rendered from the same md sources (nextjs.org/docs-style funnel after the landing) is scoped as DISCO-4.
- **Open-questions ledger** - `docs/open-questions.md`: every provisional judgment call (folder READMEs, checklist naming, dist rename, tracker default, status in front-matter, profiles split, auth/styling picks, this file's own shape) recorded with its reasoning and an open invitation to argue a better answer; a new taxonomy kind ("open question") and CONTRIBUTING's contributor entry point.
- **Product spine scoped (PDLC-1..6) + the founder's manifesto** - research (owner's private notes) maps which delivery-lifecycle artifacts the standard covers vs which still drift between departments (positioning, North Star/KPIs, analytics tracking plan, research repository, journeys, GTM/pricing); each gap gets a proposed in-repo home or federation rule. `docs/manifesto.md` states the founder's why - one repo, everything coherent and close to the code, executed by agents, verifiable by a number - with seven non-negotiables.
- **Wave 3 (owner directive: implement everything)** - SD-1..7 closed (same-PR rule, reconcile flips Open questions; rest verified already-covered); CONS-1..3 via ADR-012 (in-repo instructions are the source of truth) + conventions rule + elicitation in align/onboard; PDLC-1..6 (positioning, North Star/KPI tree + Success metric field, tracking-plan/research/journeys templates, checklist rows); DISCO-1/2 (llms.txt, degit path, repo description + topics); PROF-1/SKILL-1 (manifest profiles + self-verify --profile + stray-skill warnings); LAND-1 tail (two-paths + PO-builds-via-spec + the verbatim one-liner); DISCO-4 (dependency-free docsite renderer, 13 pages, dark-first in the landing palette); ADR-008/009/010/011 flipped to Accepted. Deliberately left out, each per its own recorded DoD: STRUCT-1 (rides alone, next PR), STARTER-1 (boot-verified own PR), STACKS-2 (needs evidence repos), NAME-1 (owner).
- **Spec Kit posture decided (ADR-013, Accepted)** - the engine is a **vendored, pinned, patched copy** (owner amendment): the agent-side Spec Kit assets (command prompts, scripts, constitution) get vendored at a pinned version with our patches baked in (capability paths, the clarify-gate hooks, statuses), synced with upstream only at release time, shipped via `dist/` with MIT attribution ("based on github/spec-kit vX.Y") - consumers stop needing upstream's CLI and stop being exposed to its breaking changes (ENG-5 lands the copy). Our `spec-*` skills stay the standard's own layer, never named speckit. Also decided: **the project name stays `repository-standards`** (NAME-1 closed; both domains already owned) and **`dist/` keeps its name** (it IS the built output).
- **STRUCT-1 executed (owner override of its rides-alone DoD)** - the zone-2 source now lives under `standard/` (specs, skills, agents, claude, github, gitleaks, decision-records, the manifest, and the shipped docs incl. templates/ideas/analytics/research/journeys); repo-own content stays at `docs/` (manifesto, faq, positioning, personas, open questions, case studies, working); `dist/` keeps its name and its layout (client paths unchanged - consumers see zero difference); reflect map, docsite map, and every repo-own link rewritten; all checks green.
- **Boot-verified greenfield starter (STARTER-1)** - `stacks/node-ts/starter/`: Next 16 (App Router, React 19) + Fastify 5 wired through the Next proxy, shared Better Auth (SQLite for zero-infra boot, Postgres swap documented), default-deny session gates on BOTH sides, CSS Modules + SCSS with the three-tier token pattern, Vitest + Playwright. Not merged on faith: installed, booted, and proven on the owner's machine (proxy-served health, curl + full Playwright sign-up -> dashboard -> /api/me journey, 6/6 unit, 5/5 e2e, build green). Template defects the boot exposed are captured as TMPL-1.
